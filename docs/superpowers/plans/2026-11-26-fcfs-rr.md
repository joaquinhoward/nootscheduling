# FCFS and Round Robin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** FCFS and Round Robin as pure, tested JavaScript functions plus a throwaway React test page that runs them.

**Architecture:** Each algorithm turns a process list into a Gantt timeline. One shared helper, `computeMetrics`, turns
any timeline into per-process results and averages. A small validation module turns raw form strings into processes.
`App.jsx` wires the three together with a plain CSS Gantt chart and a results table.

**Tech Stack:** Node 24, Vite, React 19 (JavaScript, `.jsx`), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-fcfs-rr-design.md`

## Global Constraints

- 1 to 10 processes. Arrival Time is a whole number ≥ 0. Burst Time is a whole number ≥ 1. Quantum is a whole number ≥ 1.
- Process number `pid` is 1-based and is shown as `P<pid>`. Idle blocks use `pid: "Idle"`.
- TAT = CT − AT, WT = TAT − BT, RT = first start − AT.
- Averages are numbers rounded to 2 decimals (`Math.round(x * 100) / 100`). The page shows them with `toFixed(2)`.
- FCFS ties on arrival: lower `pid` first.
- RR: processes arriving at or before the moment a slice ends join the queue **before** the preempted process.
  Same-time arrivals join in lower-`pid` order. Each slice is its own Gantt block, even when the same process runs
  again right away.
- Algorithms never mutate their input array and return `results` sorted by `pid`.
- Only FCFS and RR. No other members' algorithms, no shared UI beyond the throwaway test page.
- Work on branch `feat/fcfs-rr`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Processes entered out of order (not sorted by arrival or pid): output must be the same as for sorted input, and
  the input array must be unchanged. Tested in Task 2 and Task 3.
- First arrival after t = 0: the Gantt chart must start with an Idle block from 0. Tested in Task 2 and Task 3.
- Inputs with spaces around them (`" 3 "`) are accepted. Decimals (`"2.5"`), `"1e2"` and `"+3"` are rejected as not
  whole numbers. Tested in Task 4.
- Editing any input after a run hides the old results, so the screen never shows results for inputs that are no
  longer there. Checked in Task 5's browser check.
- Reset puts the page back to 3 empty rows, FCFS, quantum `2`, no errors, no results. Checked in Task 5.

- [ ] **Step 3: Implement `roundRobin(processes, quantum)` in `src/algorithms/roundRobin.js`**

The order of the last two lines in the loop is the documented queue rule:

```
sorted = copy of processes sorted by (arrival, pid); remaining[pid] = burst
queue = []; time = 0; next = 0
admit(t): while next < sorted.length and sorted[next].arrival <= t: queue.push(sorted[next++])
admit(0)
while queue is not empty or next < sorted.length:
  if queue is empty:
    gantt.push({ pid: 'Idle', start: time, end: sorted[next].arrival }); time = sorted[next].arrival; admit(time); continue
  p = queue.shift(); run = min(quantum, remaining[p.pid])
  gantt.push({ pid: p.pid, start: time, end: time + run }); time += run; remaining[p.pid] -= run
  admit(time)                              // arrivals up to and including slice end go first
  if remaining[p.pid] > 0: queue.push(p)   // then the preempted process
return { gantt, ...computeMetrics(processes, gantt) }
```

### Task 4: Input validation

**Files:**
- Create: `src/algorithms/validation.js`
- Test: `src/algorithms/validation.test.js`

**Interfaces:**
- Produces: `validateProcesses(rows: {arrival: string, burst: string}[]) → { processes: {pid, arrival, burst}[] | null, errors: string[] }`
  — `pid` is the row index + 1. `processes` is `null` when `errors` is non-empty.
- Produces: `validateQuantum(raw: string) → { quantum: number | null, error: string | null }`
- Exact messages (`<F>` is `Arrival Time` or `Burst Time`):
  - `Enter between 1 and 10 processes.`
  - `P<n>: <F> is required.`
  - `P<n>: <F> must be a whole number.`
  - `P<n>: Arrival Time cannot be negative.`
  - `P<n>: Burst Time must be at least 1.`
  - `Time Quantum is required.` / `Time Quantum must be a whole number.` / `Time Quantum must be at least 1.`
- A value is trimmed first. A whole number matches `/^-?\d+$/`. A negative whole number gets the negative /
  at-least-1 message, not the whole-number one.
